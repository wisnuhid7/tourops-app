---
name: Porting legacy Express apps into artifacts
description: Lessons from porting a large legacy Express+React app (custom auth, ~200+ routes) into the pnpm-workspace multi-artifact structure.
---

- When a legacy app registers all routes via a single `registerRoutes(httpServer, app)` call (not the scaffold's `router`), it's fine to keep that pattern as-is and call it directly from the artifact's `index.ts` before `httpServer.listen`, rather than forcing routes through the scaffold's `src/routes/*` convention. **Why:** rewriting ~200 hand-written endpoints into the scaffold's router style is high-risk, low-value churn for a straight port. **How to apply:** only do this for large/legacy backends being ported wholesale, not for new development.
- Preserving a legacy app's own session/auth system (e.g. express-session + connect-pg-simple + bcryptjs) instead of migrating to Clerk/Replit Auth is a reasonable scope decision for a straight port, but **audit the copied session cookie config** — legacy repos often hardcode `cookie.secure: false` "for local dev" and never revert it. Fix to be env-aware (`secure: NODE_ENV === "production"`) since production runs behind a trusted proxy (`trust proxy` already set).
- Any legacy route that server-side fetches a **user-supplied URL** (e.g. an "image proxy" endpoint) is a classic SSRF vector and commonly ships in legacy code with zero validation. Always add: scheme allowlist (http/https only), block localhost/loopback/private-IP ranges (resolve DNS, don't just string-match hostname), and require authentication — before considering the port done.
- Copying `server/lib` (or similar directories) into an artifact that already has its own `lib/` dir can silently produce a nested `lib/lib/` — always check the copied tree structure right after a bulk directory copy, not just that files "exist somewhere."
- After porting, frontend pages that import shared backend/db types (e.g. `@shared/schema` → `@workspace/db`) need `@workspace/db` added as an actual dependency in the frontend artifact's `package.json`, not just an import path fix — otherwise typecheck fails with "Cannot find module" even though the import path is correct.
